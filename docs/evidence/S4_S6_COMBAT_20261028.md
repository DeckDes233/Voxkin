# S4–S6 与群怪战斗修复

日期：2026-10-28（Asia/Shanghai）。范围：继续已有 S0–S3 修复，处理 S4–S6 和用户明确提出的群怪威胁判断、撤退、苦力怕感知。执行环境为 Windows。

## 依据与实现

通关依赖按 Java 1.21.1 核对：钻石镐用于黑曜石路线，打火石需一铁锭与一燧石，烈焰棒每根产两份烈焰粉，末影之眼每个消耗一珍珠与一烈焰粉，箭每次配方产四支。项目使用的 `minecraft-data` 1.21.1 配方枚举支持 cobblestone、cobbled_deepslate、blackstone 各自的熔炉与石镐配方；规划以单一具体配方的可用量判断，不能把不同石材相加后交给不支持该组合的 Bridge 配方选择器。

Minecraft 官方 [Enderman 说明](https://www.minecraft.net/en-us/article/enderman)确认：未激怒的末影人是中立生物；它会躲避投射物，接触液体也会瞬移。战斗策略不应把水当作定身效果，或向末影人浪费箭。相关修复同时覆盖专用猎取与通用攻击入口。

### S4

- 食物储备使用 `hunt_animal.count` 的总生肉语义，折算已有其他食物，避免有一份肉却重复发出已满足的采集目标。
- 铁镐缺失时可从木镐、石镐恢复，深层采集 deepslate；熔炉、石镐按实际可执行石材配方规划。
- 支持木板燃料，并按燃料可熔炼数量分批处理铁矿；缺木材时传递原有安全等待与阻断原因。
- 取水和找岩浆在当前候选消失、耗尽或不可达后继续有界移动搜索，沿用同一次动作的探索预算与 visited 集合。

### S5/S6

新增 `late_game_methods.py` 负责无外部 I/O 的规划，`GoalSupervisor` 继续独占派发、对账、SQLite 和预算。

- S5 根据当前维度和库存选择补给、建门、过门、堡垒、烈焰棒与珍珠任务。已进入下界后不会再次采主世界材料，已消耗的打火石原料与黑曜石不会被当成必须重复补齐的目标。
- 恢复过门时使用已确认门址提示，Bridge 仍需检查真实门块与维度变化。饥饿且无食物时优先返回主世界补给。
- S6 按已有弓箭、眼、珍珠、烈焰粉计算净缺口。找到门框后进入激活流程，不重新投眼；进入末地后不会因为用掉箭又去执行主世界猎取任务。
- 低血量战斗前先进食或等待恢复。主世界地下缺少户外资源时使用已有可验证的返地表路径。
- 既有返回门加上看不到龙不再被当作本次击杀。击杀事件需要实际观察到龙血量归零，或先观察到龙、战斗中新出现返回门且龙消失。

### 群怪与共用功能

群怪评估在接近与每次攻击时更新，考虑距离、数量、怪物类型、血量、装备，以及苦力怕接近和引爆元数据。自动攻击可优先处理更高威胁；指定目标保持原指令语义。撤退不冒充指定击杀完成。未激怒的末影人不触发普通自动反击。监守者直接规避；低装备降低群怪压力阈值，重型敌人另检查武器与实际穿戴护甲。

撤退在原有 12 格目标、4 秒寻路上限内比较周围方向，按全部可见威胁评分，结束后核对实际位移与安全分变化。实际装备的近战武器与战力评估使用同一选择逻辑。以上属于规则式决策，未知地形的可达性仍由原有寻路器判断。

共用合成另修复了原木加工误调用“合成原木”、已有木板未计入缺口、床/火把向 Mineflayer `blockAt` 传错参数，以及准备弓箭时附近无树就直接失败的问题。
