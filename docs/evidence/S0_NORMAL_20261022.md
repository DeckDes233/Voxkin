# S0 Normal 难度回归证据（2026-10-22）

## 结论

空背包 → 3 原木 → 12 木板 → 工作台 → 4 木棍 → 木镐，在 **Normal 难度**（怪物生成开启）下连续 **10 次全部通过 5/5 步**，
用时 34.3–38.5 秒，P50 36.4 秒。M2 的退出条件（10 次 ≥8 次、10 分钟内做出木镐与工作台、无人工给料）已经满足。
本轮修掉了两个真实技能缺陷：采集被误判成"被怪打断"而反复重试，以及合成时等待结果槽位必然超时。

## 本轮修掉的两个技能缺陷

### 采集：寻路被停止后被误判成"被怪打断"

现象：`动作失败 collect_blocks 试了 5 个目标，没有捡到 橡木`。桥接日志里每秒出现一次 `pathfinder.stop`，
随后打印"采集被打断，等反击结束后重试"，5 个目标全部耗尽。

根因：`bot.pathfinder.goto` 被外部停止时会抛 `Path was stopped before it could be completed!`，
旧代码把它当成怪物打断，于是对同一个目标反复重试；同时掉落物实体刚生成时还没有元数据，
拾取过滤把它漏掉。

修法：寻路结果分成 `reached` / `unreachable` / `cancelled` / `low_health` 四类，
外部停止直接结束技能，只有确实走不到才换目标；掉落物拾取等到实体出现、走��拾取范围内，
并用背包数量变化核对，捡不到就如实报"没有捡到"。战斗打断时先判断血量，血量不足就撤退等恢复。

### 合成：摆放第一个材料就必然等满 20 秒

现象：`合成工作台` 失败，detail 是 `Event updateSlot:0 did not fire within timeout of 20000ms`。

根因：mineflayer 的 `clickWindow` 点完合成格后会等服务端重发结果槽位，
而合成格还没凑齐配方时服务端不会重发，`once` 的默认超时是 20000 毫秒，于是第一个材料就卡满 20 秒。

修法：桥接自己发 `window_click` 包并按 prismarine-windows 的规则推演本地窗口状态，
只在固定间隔后等待，不再依赖结果槽位重发；材料不足时报"材料不够，还差 N 个"并把鼠标上的东西退回背包；
失败时把合成格里的材料还原，避免材料卡在窗口里。
