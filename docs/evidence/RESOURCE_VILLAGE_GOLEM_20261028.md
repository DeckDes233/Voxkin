# 资源储备、村庄补给与铁傀儡取铁

日期：2026-10-28。目标环境：Windows、Minecraft Java 1.21.1。

## 资源规划

`resource_policy.py` 将下一步的最低材料要求与储备目标分开。采木按阶段争取 8/12/16 根原木，常用石材 32，S3 铁矿 24、煤 16；已有铁锭和木板会折算，低血量或背包空间不足时不扩大采集。最低量沿用原阶段策略，储备是有界采集的软目标，未采满不会把已满足的最低需求算成失败。新参数 `mine_collect.minimum_count` 明确这一合同；普通调用不提供它时，仍严格要求原 `count`。

主世界资源观察增加 `resource_sites`，只扫描已加载的附近方块和实体。床、箱子采用村民/钟作为村庄线索，不宣称识别建筑名称或预知箱中物品；铁匠铺箱子与其他村庄箱子使用同一真实开箱流程。已知庇护所附近的床和箱子排除，干草可在其他地方收集。

阶段任务优先利用当前可见的资源机会，食物储备目标按阶段为 8/12/16/24。现成床、箱中面包、铁锭、工具、护甲等都按实际库存缺口处理。已查过的地点记入当前目标账本；空箱、不可达资源和未完成的取铁机会不会无限重复，随后继续原采集路线。S6 要塞搜索已经开始后不插入新的补给绕路。旧 Bridge 没有资源观察字段时保持旧参数兼容。

干草掉落的是干草块自身，先拾取再拆成麦子。项目当前 `minecraft-data` 的 Java 1.21.1 配方枚举已核实：1 hay_block → 9 wheat，3 wheat → 1 bread。没有工作台时保留干草/麦子，由阶段规划补工作台和面包。官方 [Hay Bale 说明](https://www.minecraft.net/fr-ca/article/hay-bale)也说明九份麦子可压成一捆，且可在合成格取回麦子。

## 独立技能

- `loot_village`：读取真实资源线索、拾取闲置床、检查村庄箱子、收集干草并加工面包。支持目标库存数量、食物/床目标、有限探索与已访问地点。窗口在结束或取消时关闭，结果记录库存变化与剩余缺口。
- `harvest_iron_golem`：指定一只真实可见的铁傀儡，校验武器、垫脚材料和地形，确认三格柱的实际方块与高度后攻击；蹲伏防跌落，按冷却等待下降阶段与有效攻击距离。跳劈请求不等于服务器已确认暴击。实际收到铁锭才算取铁成功。

本轮不启动 Minecraft，不改变旧任务预算、pending action 或存档；`runtime_blocked=true` 保持。离线逻辑通过不能替代真实服务器上的垫柱、跳劈和容器同步验收。当前村庄识别采用附近村民/钟的线索，不等于服务器提供了建筑归属；同一村庄范围内的玩家箱子如果不在已知庇护所保护区，也无法仅凭方块判断其所有者。
