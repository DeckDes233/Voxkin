# S0–S3 生存流程与修复（2026-10-28）

## 版本与流程依据

本轮先核对通关流程再修改策略。目标是 Java 1.21.1；本地 `minecraft-data` 3.117.0 对该请求返回 `minecraftVersion=1.21.1`、protocol 767、dataVersion 3955。配方、矿物掉落和采收工具等级以该版本数据核对，不能拿后来版本的新木材或矿物机制代替。

完整路线是：取得木材与基础工具，解决食物和夜间安全，准备铁制工具与桶等物资，进入下界取得烈焰棒和末影珍珠，合成末影之眼，找到要塞并激活末地传送门，进入末地击败末影龙、经返回传送门离开。项目 S4 选择钻石镐路线，S5/S6 再处理下界与末地；本轮仅修 S0–S3。

官方依据：

- [首日生存](https://www.minecraft.net/en-us/article/how-survive-your-first-day)：木材、工作台、木镐、圆石、石器是基础依赖链；夜间需要安全地点。
- [Java 1.18 矿物分布调整](https://www.minecraft.net/en-us/article/caves---cliffs--part-ii-out-today-java)：铁矿地下分布偏向 Y=16，山地高处也生成铁矿。Y=16 是本项目选取的地下路线目标，不代表其它高度没有铁。
- [要塞与末影之眼](https://www.minecraft.net/pl-pl/article/stronghold)：珍珠和烈焰粉合成末影之眼，眼用于定位和激活传送门；投掷可能损耗，不能只准备恰好填框的数量。
- [龙蛋](https://www.minecraft.net/es-es/article/dragon-egg)：串联下界、末影之眼、末地与末影龙的流程。

床、全套铁甲、钻石镐不是所有原版通关路线的共同硬门槛。Voxkin 的阶段目标是选定路线的验收契约；修复不擅自扩大它们。S3 标题改为“铁制工具、盾与空桶”，与实际验收一致。

## S0–S3 材料依赖

| 阶段 | 最终验收保持不变 | 配方依赖与策略 |
| --- | --- | --- |
| S0 | 工作台、木镐各 1 | 工作台 4 木板；木镐 3 木板、2 木棍。原木每次合成产 4 木板，2 木板产 4 木棍。任意主世界树种均可。 |
| S1 | 石镐、石剑、熔炉各 1 | 分别消耗 3、2、8 圆石，共 13；工具合计另需 3 木棍。缺工作台或采石工具时先恢复依赖。 |
| S2 | 足够饥饿值、已封闭且人在内部的庇护所、室内床；必要时有过夜回执 | 床需 3 同色羊毛和 3 木板。已有剪刀则剪毛，有 2 铁锭可做剪刀，否则猎取成年未剪毛羊；不强制为床先找铁。先处理饥饿和夜间危险。 |
| S3 | 铁镐、铁剑、盾、空桶各 1 | 铁锭净成本 3+2+1+3=9，另需工具木棍 3、盾木板 6；扣除已有成品、铁锭和粗铁后计算缺口。 |

Java 原版配方标签允许多种木材；当前 Mineflayer 数据把配方展开为具体物品组合。因此调度器保证至少一条具体配方能执行，不用“多种木板加起来够了”代替可执行性。背包里的不同原木可分批加工，合成 `count` 表示期望产物数，不是配方执行次数。

## 实施变更

1. S0/S1 在每次观察后重新计算未满足成品的直接依赖，旧线性游标不再决定它们的下一动作。死亡、丢失或消耗材料后能够重建工具链；旧 pending action 仍先按既有协议对账，未重置任务时间和动作预算。
2. `mine_collect block=wood_log` 搜索八种主世界原木，按这些物品的实际库存合计验收。缺候选、不可达、已采空都继续使用既有有界移动搜索；不会依次把整片区域按八个树种重复扫描。
3. S2 羊毛按一种颜色计数，排除幼羊和已剪毛羊；没有目标时使用动物搜索路线。饥饿时不排除羊，避免附近只有羊却坚持找其它肉源。
4. S3 首先搜索可采集铁矿；普通/深层铁矿同时匹配。无进展后每段最多下降 12 格朝 Y=16 推进，随后水平探露；最多 12 段，纳入原任务预算。明确 `no_safe_stair` 后改走水平路线，再依据新位置重评；结果不明的非重放动作仍阻断。每段完成后重新搜索，找矿失败计数按所在路线段区分。
5. 共用燃料表与选择函数支持煤、木炭、九种主世界木板；不把绯红、诡异木板或按错误时长计算的木棍当成燃料。批量熔炼选择库存足够的燃料，并显式传给底层熔炉。S3 每批至多 8 个，能先烧已有燃料支持的部分，保留尚未制作的盾牌所需木板。
6. 挖掘前在工具切换后检查 `canHarvest`，工具等级不足不破坏矿石。煤矿、铁矿和钻石矿均识别普通与深层变体。
7. 新增参数同步到技能清单。共用木材 helper 对 S4 的库存计数和搜索记录兼容也已处理，未改变 S4 的目标与路线预算。
