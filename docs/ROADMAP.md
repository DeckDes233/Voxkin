# 路线图

按优先级排列。P0 是让系统在真实游戏中可用的必要条件，P1 是体验与可维护性，P2 是长期目标。

## P0

| 任务 | 依赖 | 验收条件 |
| --- | --- | --- |
| 真实 DeepSeek 延迟测量 | 用户授权 `DEEPSEEK_API_KEY` | `bench` 输出真实首 token 与首次可听延迟，写入 `BENCHMARK_RESULTS.md` |
| 麦克风实时链路联调 | 可用麦克风 | 说话结束后 2 秒内开始播放回复，打断可用 |
| Minecraft 动作结果回述 | 事件总线 | 动作成功或失败后，玩家能在 1 秒内听到一句结果说明 |
| 音频投递可靠性 | 现有 Mod | 连续 10 轮不重叠、不丢段；新回合能立即截断旧音频 |
| TTS 首句优化 | 无 | 首句控制在 12 字以内时，TTS 首段低于 500 ms |

## P1

| 任务 | 依赖 | 验收条件 |
| --- | --- | --- |
| 流式识别 | sherpa-onnx 中文模型 | 说话过程中出中间结果；最终文本延迟低于 800 ms |
| 专用客户端 Mod | Fabric 1.21 + JDK 21 | 通过 WebSocket 接收 PCM，送入游戏声源；支持按距离衰减与打断 |
| 情绪与韵律 | GPT-SoVITS 参考音频分组 | 至少三种语气可选，切换不需要重启服务 |
| 记忆与关系 | 事件存储 | 记录真实游戏事件（死亡、救援、建造），对话中可检索 |
| Studio 诊断增强 | 无 | 显示每轮各阶段耗时曲线与失败原因分布 |

## P2

| 任务 | 依赖 | 验收条件 |
| --- | --- | --- |
| CosyVoice 3.0 对照实验 | 独立环境与模型 | 同文本、同硬件下首段延迟与音色相似度可对比 |
| 多人游戏 | 专用 Mod + 服务端 | 多个玩家各自听到空间化的 AI 语音 |
| YSM 动作联动 | YSM 接口 | 说话时触发嘴部动作，动作与音频时间一致 |
| 跨游戏适配 | 桥接协议 | 新增游戏只需要实现桥接客户端，不改 Core |

## 明确不做

- 不在第一阶段重写 MindCraft；桥接进程与 MindCraft 改造是两条独立的可评估路线。
- 不支持把服务暴露到公网；默认只监听 `127.0.0.1`。
- 不在仓库中存放模型权重、参考录音或真实密钥。
