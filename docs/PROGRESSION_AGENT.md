# 通关 Agent：规划、执行、验证的循环

## 结论

值得做，但先做 **TaskRunner**，不要一上来做“模型训练”。让一个 Agent 按 Minecraft 的通关顺序推进，核心是三件事：

1. 一个稳定的阶段目标表，明确每一步的完成条件；
2. 一个执行循环，调现有技能、读世界状态、判断成功或失败；
3. 一个失败后的重规划入口，而不是无限重试同一步。

“模型-模型迭代”可以放在第二阶段：把每次执行的 `state → action → result → outcome` 落成轨迹，先用规则评估，再决定是否做微调或偏好优化。在线自我训练风险太高，不适合直接放进游戏循环。

## 三个角色

| 角色 | 职责 | 频率 | 模型 |
| --- | --- | --- | --- |
| Planner | 选下一阶段、拆步骤、失败后改计划 | 每阶段一次，失败时一次 | 强模型，低频率 |
| Executor | 把一步翻译成工具调用，处理即时反馈 | 每步 | 快模型，可复用现有对话模型 |
| Verifier | 用背包、坐标、方块、血量等硬条件判断成功 | 每步结束 | 规则，不调用模型 |

语音只播报阶段完成、失败原因和需要玩家决定的事，不逐条念步骤。

## 阶段表

| 阶段 | 目标 | 完成条件 |
| --- | --- | --- |
| S0 | 木头与工作台 | 背包有 `wooden_pickaxe`、`crafting_table` |
| S1 | 石制工具与熔炉 | `stone_pickaxe`、`stone_sword`、`furnace` |
| S2 | 食物与庇护所 | 食物 ≥8，夜晚有床或封闭空间 |
| S3 | 铁装与盾 | `iron_pickaxe`、`iron_sword`、`shield`，铁锭 ≥6 |
| S4 | 钻石与附魔 | `diamond_pickaxe`、`enchanting_table`，钻石 ≥3 |
| S5 | 下界与烈焰棒 | 烈焰棒 ≥7，末影珍珠 ≥16 |
| S6 | 要塞与末地 | 进入末地，击败末影龙 |

每一阶段只依赖前一阶段的产出。阶段表放在 `src/voxkin/agent/progress.py`，是唯一事实来源。

## 执行循环

```text
读取当前阶段和目标
  → Planner 生成 1-5 步计划（每步带完成条件）
  → Executor 调技能执行一步
  → Verifier 用世界状态和背包检查
      ├─ 成功：记录，进入下一步
      ├─ 可恢复失败：重试一次，换参数
      └─ 连续失败两次：回到 Planner 重规划
  → 阶段完成：播报，进入下一阶段
```

每一步都有超时、重试上限和取消入口。玩家说“停”“先打怪”“跟我来”时，当前任务暂停，玩家指令优先。

## 模型-模型迭代

第一阶段只记录轨迹，不做训练：

```json
{"stage":"S1","goal":"craft stone_pickaxe","state":{...},"tool":"craft","args":{...},"result":"ok","verified":true}
```

用途：

- 统计哪类步骤失败率最高；
- 给 Planner 提供少样本示例；
- 以后做离线微调或偏好数据。

不建议在线让两个模型互相“训练”：游戏状态不可逆，错误动作会丢物品、死亡、破坏建筑。

## 分阶段交付

| 批次 | 内容 | 验收 |
| --- | --- | --- |
| P1 | 阶段表、Verifier、只读状态检查 | 给定背包能判断当前处于哪一阶段 |
| P2 | Executor 调现有工具，完成 S0 | 从空背包做出木镐 |
| P3 | 失败重试与 Planner 重规划 | 木头不够时换目标或求助 |
| P4 | 任务持久化与恢复 | 重启后从上次步骤继续 |
| P5 | 轨迹记录与评估 | 输出每阶段成功率、平均步数 |

## 风险

- **死亡循环**：低血、夜晚、无食物时继续做危险步骤。规则是生存优先，任务暂停。
- **资源误用**：把钻石做成镐子以外的物品。阶段表要限制配方白名单。
- **规划漂移**：Planner 生成无法验证的步骤。每步必须有可机器检查的完成条件。
- **上下文膨胀**：不要把全部历史塞给 Planner，只给当前阶段、背包摘要、最近三次结果。
- **语音刷屏**：只播报阶段完成和失败，不播报每次工具调用。
